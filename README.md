# VPN-бот

Телеграм-бот на Python и aiogram 3. Оплата ручная: человек выбирает тариф, получает QR и код, нажимает «Я оплатил», администратор подтверждает заявку и вставляет ссылку доступа.

## Сценарий

1. Пользователь открывает бота и выбирает тариф.
2. Бот создаёт заявку и присылает QR вместе с кодом вида `VPN-AB12CD`.
3. Пользователь переводит сумму и указывает код в комментарии к платежу, затем нажимает «Я оплатил».
4. Администратор видит заявку в `/admin` (и в личном сообщении), подтверждает её и отправляет боту ссылку доступа.
5. Бот пересылает ссылку пользователю. Повторно она лежит в «Мои заказы».

Отклоненная заявка остаётся в истории со статусом «отклонена». Новая неоплаченная заявка отменяет предыдущий неоплаченный счёт того же пользователя. Заявка, которая уже на проверке, при этом не трогается.

## Запуск

Нужен Python 3.11+.

### Docker + Postgres (рекомендуется)

```bash
cp .env.example .env
# заполните BOT_TOKEN, ADMIN_IDS, PAYMENT_DETAILS, POSTGRES_PASSWORD
docker compose up -d --build
docker compose logs -f bot
```

Подробнее: [`docs/DEPLOY.md`](docs/DEPLOY.md).

### Локально на SQLite

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# DATABASE_URL=sqlite+aiosqlite:///data/bot.db
python -m bot
```

В `.env` укажите токен бота и Telegram id администраторов через запятую. Каждый администратор должен один раз открыть бота и нажать `/start`: иначе Telegram не даст прислать ему заявку. Сами заявки всё равно копятся в `/admin`.

Проверка:

```bash
pip install -r requirements-dev.txt
ruff check bot tests alembic
python -m pytest
```

## Оплата и QR

`PAYMENT_DETAILS` — текст реквизитов в подписи к QR (СБП, карта, получатель).

`PAYMENT_QR_PAYLOAD` — необязательная готовая строка для QR, например банковская ссылка. Пока поле пустое, QR кодирует название, реквизиты, сумму и код платежа. Код в подписи остаётся в обоих режимах: по нему администратор сверяет перевод.

Цены стартовых тарифов заданы в `bot/services/orders.py` (`TARIFF_SEED`, суммы в копейках). Повторный запуск не перезаписывает уже созданные тарифы. После первого старта цену меняют в таблице `tariffs`.

Ссылка доступа — одно сообщение без пробелов, внутри есть `://`. Подходят `https://...` и ссылки вида `vless://...`.

## Состояния заявки

| Статус | Когда |
| --- | --- |
| `awaiting_payment` | QR показан, оплаты ещё нет |
| `pending_review` | Пользователь нажал «Я оплатил» |
| `fulfilled` | Администратор подтвердил и сохранил ссылку |
| `rejected` | Администратор отклонил заявку на проверке |
| `cancelled` | Пользователь отменил счёт или начал новый |

Пока бот работает в одном процессе: SQLite-файл `data/bot.db` и память aiogram для шага «вставьте ссылку». Незавершённый ввод ссылки сбрасывается при перезапуске, сама заявка остаётся на проверке.

## Каркас

```
bot/
  __main__.py          запуск polling
  config.py            настройки из .env
  models.py            пользователи, тарифы, заявки
  handlers/user.py     тарифы, QR, «Я оплатил», мои заказы
  handlers/admin.py    очередь, подтверждение, ссылка
  services/orders.py   переходы статусов
  services/payments.py код платежа и QR
```

Дальше сюда ложится выдача доступа из панели (3x-ui, Marzban и аналоги) вместо ручной вставки ссылки.
