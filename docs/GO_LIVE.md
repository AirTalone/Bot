# Go-live checklist

Отмечайте пункты перед публичным анонсом. Источник правды для фазы 9.

## A. Инфраструктура

- [ ] VPS бота: Docker + `compose.prod.yml` подняты (`deploy` user, не root-процесс приложения)
- [ ] `.env` только на сервере, права `600`, нет в git
- [ ] `ufw` (или аналог): SSH ключом; Postgres/бот не слушают мир
- [ ] `systemctl enable vpnbot` (или эквивалент) — переживает reboot
- [ ] Cron бэкапа Postgres + хотя бы один offsite-копипаст дампа
- [ ] Restore drill выполнен хотя бы раз (`docs/BACKUP.md`)

## B. Продукт / смоук

- [ ] Бот отвечает на `/start` с **продакшен**-токеном
- [ ] Админ один раз нажал `/start` (иначе push-заявки не дойдут)
- [ ] После «Я оплатил» админ получает заявку
- [ ] Confirm (панель или ручная ссылка) доставляет доступ пользователю
- [ ] Клиент реально ходит в интернет через ноду
- [ ] Reject не выдаёт доступ
- [ ] Повтор paid / confirm / Stars charge_id безопасны (идемпотентность)
- [ ] `/help`, «Мои заказы», техработы переключаются из `/admin`
- [ ] (если Stars) тестовая оплата XTR на минимальном тарифе
- [ ] (если панель) `PANEL_ENABLED=true` и выдача `subscription_url` ок

## C. Качество и секреты

- [ ] CI зелёный (pytest + ruff) на релизной ветке
- [ ] Секреты не в git (`gitleaks` / ручной поиск `BOT_TOKEN|PASSWORD`)
- [ ] `security-audit` скилл: нет открытых Critical/High без решения
- [ ] `parallel-code-review` на релизной ветке (по возможности)

## D. Мягкий запуск (48 часов)

1. Включите техработы = выкл, тарифы финальные.  
2. Зовите **5–10** друзей, не публикуйте канал.  
3. Собирайте баги: оплата, ссылка, клиенты iOS/Android, панель.  
4. Смотрите `admin_audit_logs` / ошибки панели / Sentry.  
5. Почините блокеры, сделайте свежий бэкап.

## E. Публичный запуск

- [ ] Все пункты A–C зелёные  
- [ ] Мягкий запуск без критичных дыр  
- [ ] Тексты поддержки / оферты на месте (хотя бы черновик)  
- [ ] Анонс + мониторинг первые часы (`docker compose logs -f bot`)  

Откат: техработы в `/admin`, при необходимости `docker compose -f compose.prod.yml stop bot`.

После публичного запуска ведите календарь из [`docs/OPS.md`](OPS.md) (`/report`, патчи, ротация секретов).
